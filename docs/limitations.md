# Known limits

These are current boundaries, not capabilities inferred from prompts or a passing demo.

- **Languages:** deterministic analysis targets Python, JS/JSX and TS/TSX. Other ingested text may supply context; Go/Java/Rust do not have dedicated semantic analyzers. JS/TS support is specified in [the capability matrix](language-support.md).
- **Semantics:** Python/TypeScript resolution is conservative. Dynamic dispatch, metaprogramming, runtime monkeypatches, complete framework/dependency builds, return-shape compatibility and whole-program taint proof are not established. A function named `sanitize` is not proof of safety.
- **TypeScript:** the virtual compiler uses snapshot-local modules, selected root tsconfig options and included declarations. It does not run project plugins/configuration or install dependencies. Selected type diagnostics and syntax validation are not full build certification. JavaScript `checkJs` is disabled.
- **Context and coverage:** quick reviews prioritize bounded context; deep reviews batch files within budgets. Omitted files, failed stages and unresolved evidence remain visible. Related-test hints are not measured test coverage. Missing model output cannot establish a clean result.
- **Source limits:** at most 2,000 text files and 20 MiB of included source per inventory; individual Git/local source files over 500 KiB are skipped. Folder requests also enforce their own 512,000-character/file and total-size checks. Binaries, generated/dependency folders, symlinks and submodules are not analyzed as ordinary source. These are source-inventory caps, not a universal Git network-download cap.
- **Runtime limits:** defaults are a 180-second review deadline, 12 model calls, 24 tool calls, three attempts per request and a 45-second provider request cap; validated RunConfig/operator settings can change them. Two local review slots and a provider concurrency limit apply. Deadlines are cooperative across stages and subprocess/HTTP timeouts, not instantaneous preemption of every Python instruction.
- **Provider availability:** actual live structured reviews and some tools succeeded; complete independent live challenge and ablation acceptance remain unproven under observed overload, quota and timeout errors. Returned token metadata is measured; error responses may omit billable usage. An API mode switch does not guarantee new quota.
- **Evidence:** deterministic findings, model source assessments and executed tests stay distinct. Citation matching supports source provenance, not causal correctness by itself. Model refutation cannot remove the underlying static observation.
- **Execution:** prepared trusted profiles and images are required. Python/JS/TS fixture differential checks passed, plus a custom operator contract; universal project compatibility and automatic safe test discovery are not implemented. Runtime success proves only the exercised assertions and environment.
- **Access and persistence:** this is a single-process, single-operator application. The shared token is not per-user tenancy. GitHub connection tokens are held in memory and require reconnect after restart; automatic refresh is absent. Active jobs become interrupted; source-pinned resume is a new run, not continuation of an in-flight HTTP generation.
- **Publication:** enabled credentials and explicit action are required. Local serialization and remote markers reduce duplicates; they are not a distributed exactly-once guarantee. Real GitHub authorization/private access, external publication and Actions execution still need authorized environment checks.
- **Data handling:** known credential files and private keys are excluded from source analysis; templates remain allowed. Credential-bearing arbitrary source/configuration and Git object history require care. Old checkpoints containing blocked credential paths require fresh ingestion. Redaction is best effort. Repository exclusions suppress findings and are not a privacy boundary. Snapshots/caches contain source; operators control retention and deletion. Automatic TTL cleanup and production multi-tenant retention controls are not implemented.
- **Evaluation and release:** independent annotations/adjudication and complete live comparisons are pending. Self-authored fixtures and static smoke metrics cannot establish production accuracy. Public hosted deployment, final video/submission links and team/member fields remain release tasks requiring actual user information and authorization.
