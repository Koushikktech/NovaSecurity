# Small developer exercise (not conducted)

No participants are currently available. This protocol prepares future validation; it is not evidence of time saved.

Recruit 3–5 developers who did not build Proofline. Record experience, consent, task order and any assistance. Use four matched development-corpus tasks per participant, two in each condition: source/diff plus static output, or source/diff plus full Proofline output. Counterbalance order and task assignment. Never show one person the same task in both conditions. Give each task a ten-minute cap, identical instructions, and no hints.

Ask for the trigger, consequence, affected code and proposed next action. Record correct diagnosis against established labels, elapsed time, incorrect conclusions, timeout, whether evidence was inspected, and whether they would act on the finding. A stated intention is not actual patch acceptance or a merged fix. Keep failed tasks and report individual outcomes alongside paired descriptive summaries. A tiny study does not establish production-wide time savings.

Suggested recording columns: participant ID, experience, task ID, condition, order, elapsed seconds, timeout, correct diagnosis, correct location, suitable action, evidence inspected, would act, assistance, comments. Do not place personal contact information in public results.
